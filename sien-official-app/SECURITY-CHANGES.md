# 監査指摘への修正

## 本番反映時の設定

- `NEXTAUTH_SECRET` を必須にしました。未設定時は管理者ログインを拒否します。既存の強い秘密値を維持してください。
- 回数制限は既存の PostgreSQL を共有ストアにします。初回の対象API呼び出し時に `ApiRateLimit` テーブルを作成します。DBユーザーに CREATE TABLE 権限がない運用では、デプロイ前に下記SQLをDB管理者が実行してください。既存の顧客テーブルやデータは変更しません。
- 回数制限の保存先が使えない場合、注文・法人フォーム・AI API は503を返し、DB保存・通知・AI呼び出しを開始しません。

```sql
CREATE TABLE IF NOT EXISTS "ApiRateLimit" (
  "key" TEXT PRIMARY KEY,
  "count" INTEGER NOT NULL,
  "expiresAt" TIMESTAMPTZ NOT NULL
);
```

## 制限と動作

| 機能 | 上限 |
| --- | --- |
| 管理ログイン | 全体10回/15分（成功・失敗ともに消費） |
| 通常注文 | 全体60件/時、メールアドレスごと3件/時 |
| 法人問い合わせ | 全体30件/時、メールアドレスごと2件/時 |
| 管理用AI | 返信・告知文の合計30回/時 |
| 公開チャット | 全体20回/分、200回/24時間 |

固定期間のカウンターをSQLの単一UPSERTで更新します。並列リクエストや複数インスタンスでも上限を共有します。利用者が指定できるIPヘッダーは信頼しません。制限キーにメールアドレスの平文は保存しません。上限は意図的にサイト全体にも設けているため、集中アクセス時は正規の利用者にも429が返ります。これらはアプリケーションの費用・送信回数制限であり、ネットワーク全体のDDoS対策を代替しません。

注文ではプランIDとオプションIDのみを選択情報として受け取り、現在の有効なDBレコードから金額を再計算します。従来の管理画面表示との互換性のため、保存する `Order.planId` は検証済みプラン名のスナップショットです。AI返信は過去のID・日本語名・旧識別子を解決します。要相談の金額は確定金額として保存せず、`price` をnullにします。

2026年7月17日に終了したサマーセール専用フォームは受付終了ページにしました。通常フォームへのリンク先で現在の受付状態を確認できます。

法人向け自動返信は固定文面と公式サイトURLのみとし、第三者が入力した本文・名前をメールに転送しません。管理者通知には問い合わせ内容への導線を残します。

管理ログインも共有DBの制限を使用します。入力ユーザー名を変えても回数制限を回避できません。単一管理者の運用を前提に全体で10回/15分とし、上限到達時やDB障害時にはログイン画面に案内を表示します。第三者が上限を消費した場合、正規の管理者も期間が終わるまでログインできません。

ブログ・ニュース本文は `rehype-sanitize` の許可リストで表示時に処理します。イベント属性・危険なURL・スクリプトや埋め込みなどを除去し、表・画像・詳細表示・既存の要約ボックスを残します。見出しIDには安全な接頭辞を付け、本文内のリンクも合わせて調整します。記事の保存内容は変更しません。

公開ページの受付設定取得は読み取り専用にしました。レコード未作成時は表示用の既定値を返し、初期レコードは管理者が設定を保存した際に作成します。

## ローカル確認

```powershell
node --test tests/security.test.cjs
node node_modules/typescript/bin/tsc --noEmit --incremental false
```

回帰テストはDB・認証・メール・AIを代替実装に置き換えます。本番DBへの書き込み、メール送信、AI課金は行いません。本番のDB権限・ログインCookie・実メール配信はデプロイ環境で別途確認が必要です。
