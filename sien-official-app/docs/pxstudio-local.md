# PXstudio CSV取り込み・送金月別集計

実装対象は `/admin/pxstudio` と `/api/admin/pxstudio/import`。本番未反映。本番DBの変更、既存案件への転記、売上合算は実施していない。

上記と以下の検証記録はローカル実装時点の状態。2026年11月13日の後続依頼で本番反映とバックアップが承認された。公開手順は `pxstudio-release.md`、実行結果・暗号化バックアップ・本番照合記録はGit対象外の `audit/pxstudio-release-2026-11-13/` に保存する。

## データと集計

- `PxEntry`：CSVの9項目、元のセル、内部ID、更新番号を保持。送金日は日付文字列で保存し、時差で月を変えない。
- `PxImport`：元CSV、ファイル名、取り込み日時、追加・更新・スキップ・金額不一致の件数を保持。
- `PxImportChange`：全入力明細の処理と、更新前後の値を保持。削除APIは設けていない。
- 制作費、手数料、源泉徴収、手取りは独立したCSV記載額。差額を自動補正しない。制作費の税込・税抜もCSVから推定しない。
- 月別・年別は送金日基準。表示件数は案件数ではなく明細数。未収録期間を売上ゼロと確定しない。現在はCSVの全支払いステータスを集計し、その旨を画面に表示する。
- `Order` / `PaymentRecord` / `Expense` と関連・転記・合算しない。既存集計処理は変更していない。

## 取り込み

UTF-8（BOM可）、指定の9列、最大1MB・2,000明細。引用符、カンマ、改行入りセルに対応。不正な列数、日付、金額、文字コードは全体を拒否する。入力中の文字列をHTMLや数式として実行しない。

1. CSVを選ぶと読み取り専用で照合する。確認時点ではDBに保存しない。
2. 各明細に「追加」「登録しない」「既存明細を更新」を選ぶ。同じ楽曲・カテゴリ・依頼者の既存明細を候補にし、その他の既存明細も手動選択できる。
3. 完全一致が1件でCSV内に同内容の複数行がなければ「登録しない」、候補なしは「追加」を初期選択する。候補のある変更行や同内容の複数行は選択必須。
4. 更新先と全9項目の差分、金額不一致を確認し、チェックを入れて確定する。IDがないため、候補なしでも名称・日付が変わった既存取引の可能性がある。自動判定だけで同一取引とは断定しない。
5. 保存時にCSV・明細の順序・登録済みデータの版を再確認。署名付き確認情報は30分で失効する。古いCSVの変更も更新候補にとどめ、自動で巻き戻さない。
6. PXstudio専用のDBロックとトランザクションで全体を確定。失敗時は取り込み履歴も明細も部分保存しない。

内容ハッシュは全9項目の組み合わせを行順に依存せず照合し、同内容の行が何行あるかも保持する。ファイル名、BOM、改行コード、行順が変わった同内容CSVも二重登録しない。取り込み済みファイルの再送は、後に明細が更新されていても再適用しない。確定した「登録しない」も取り込み履歴に残り、同内容CSVの再送では処理を変更しない。

案件ID・明細IDがない限り、別CSVにある完全一致行が同一取引か、同内容の別取引かの完全自動判定はできない。指紋自体を明細の一意制約にせず、確認して別明細を追加できる設計。ファイル内容ハッシュにはDBの一意制約を設定している。

## ローカル検証

通常の `.env` のDB接続先を使って移行・seedを実行しない。既存の専用QAスクリプトで、メモリ内PostgreSQL・架空の既存案件・ローカルに固定した通知先を使用する。

```powershell
# クライアント再生成のみ。DBへの接続・移行は行わない。
node node_modules/prisma/build/index.js generate
# 専用ターミナルで起動。終了時にメモリ内DBは消える。
node scripts/qa-environment.mjs
```

別のターミナルで以下を実行する。統合テストは空のPXstudioテーブルを必要とするので、再実行時はQA環境を終了して起動し直す。既存テーブルを削除する初期化処理はない。

```powershell
node --test tests/pxstudio.test.mjs
node scripts/qa-pxstudio.mjs
# 添付CSVの全9項目保存も調べる場合：
node scripts/qa-pxstudio.mjs "CSVの絶対パス"
```

管理画面：`http://127.0.0.1:3002/admin/pxstudio`。QA専用ログインは `qa-admin` / `qa-only-password`。画面には検証環境である旨を表示する。CSVを指定した場合、その内容はローカルのメモリ内DBだけに保存する。

本番向けには追加だけのSQL `prisma/migrations/202611130001_pxstudio/migration.sql` を準備した。今回は本番へ適用していない。既存の監査用移行スクリプトへ自動追加していない。将来の公開時には、バックアップとDB構成を確認して、この追加スキーマを先に適用する必要がある。切り戻し時も既存・新規データを削除する移行は行わない。

## 検証状況

- 新規テスト12件成功：CSV形式・金額保持・重複候補・同内容複数行・署名と競合・送金月境界・追加SQL・確認画面の保存制御。
- 隔離DB：認証とOrigin、読み取り専用プレビュー、同時再送、並べ替え再送、明示更新と履歴、部分期間の保持、古い確認内容の拒否、保存失敗時の全体取消、添付CSV全項目の保持、既存テーブル不変を確認。
- 期間が重なる別CSVでは一致行を登録せず新規行だけを追加できること、確認後に明細の行順を変えた場合は保存を拒否することも確認。添付CSVでは70明細を全9項目保持し、28件の金額不一致をそのまま残した。QA画面には添付CSV以外の架空テスト明細も含まれる。
- 型検査、Lint、本番形式ビルドを実施。ビルド時のDB接続先もローカルQAに固定。
- 初回検証では既存のアーカイブ復元テストが失敗し、Chromeのファイル選択も権限・URLの安全確認で停止した。以下の追加依頼で原因を修正し、アプリ内ブラウザーで未確認部分を検証した。

## 追加検証・アーカイブ修正（2026年11月13日）

### アーカイブ復元

原因は `OrderListClient` がアーカイブ一覧にも通常一覧と同じ「進行中」の初期絞り込みを適用していたこと。納品済み・キャンセル済みの行が隠れる実際の表示不具合だった。

- アーカイブのステータス未指定時は「すべて」を初期表示する。通常一覧の初期表示は従来の「進行中」を維持。
- アーカイブでも明示的なステータス絞り込みは適用する。最初のタブの表示も「すべて」に合わせる。
- スマホの復元ボタンにも、PCと同じ操作ラベルを追加。
- 元の復元テストに加え、全ステータス表示・明示的絞り込み・通常一覧の初期表示をまとめて検証する回帰テストを追加。全101テストが成功。型検査・Lintも成功。
- 専用の架空案件をアプリ内ブラウザーの390px幅で復元し、通常の納品済み一覧へ戻ることを確認。DB照合で `isArchived` と `updatedAt` 以外の全項目が同じで、確定売上3,210円と売上計上日も保持されることを確認。

### ブラウザー経由のCSV取り込み

本番ではなく `127.0.0.1:3002` とメモリ内QA DBだけで実施。ブラウザー拡張やOSの権限を変更せず、既に開いていたアプリ内ブラウザーを利用した。

1. 添付の元CSVをファイル選択から指定し、「取り込み済み」で再登録されないことを確認。
2. PC幅1280pxで `tests/fixtures/pxstudio-browser-initial.csv` を選択。確認画面は3明細追加・金額不一致1件。確認段階のDBは74明細のままで、保存ボタンは確認チェック前に無効。確定後に3明細追加されることを確認。
3. スマホ幅390pxで `tests/fixtures/pxstudio-browser-overlap.csv` を選択。変更行の更新先を選び、制作費15,000円→16,000円と他項目の差分を確認。確定後の結果は追加1・更新1・登録しない1。
4. 同じ楽曲の別日・追加料金明細を残し、CSVから省かれた行も保持。手取り11,700円・手数料0円・源泉徴収1,194円は補正せず保存。差額は2,106円→3,106円と警告表示が変わることを確認。
5. 差分CSVの再選択で「取り込み済み」と表示され、保存ボタンがなく、DB件数が増えないことを確認。最終件数78、専用の架空依頼者の明細は4件。
6. 既存の依頼・入金・経費・法人問い合わせ・設定を検証前後で照合して一致。復元検証のために新規作成した専用案件だけを比較対象から除外している。既存の本番データには接続していない。

- 明細表は幅326pxのコンテナ内で表幅1,054pxを保持し、横スクロール可能。全体の幅を押し広げない。
- 年・月の変更、依頼者名の検索、スマホメニュー、明細の処理・更新先の選択、保存操作を確認。
