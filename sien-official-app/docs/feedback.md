# 録音・歌唱フィードバック

## 使い方

管理画面 → 依頼管理 → 依頼詳細 →「フィードバックを作成・編集」。
クライアント名・楽曲名・依頼IDは保存済みの依頼から参照します。
依頼情報の変更は依頼詳細で行い、フィードバック画面を再読み込みします。

1. 総評・よかったところを入力します。
2. 録音４項目・歌唱４項目の評価とコメントを入力します。
3. 改善ポイントを最大３つ、必要な数だけ入力します。
4. 継続利用の場合は前回からの変化を入力します（自動比較ではありません）。
5. 内容プレビューで確認し、「保存してPDFダウンロード」を押します。

途中で「下書き保存」ができます。未評価の項目がある場合や、確認対象外以外のコメントが空の場合はPDF出力を止めます。
改善ポイントを使用する場合は見出し・所見・具体的な試し方の３欄が必要です。
任意項目は空欄ならPDFに載りません。PDFは文章量に応じて自動改ページします。
AI自動生成やクライアントへの自動送信、料金・オプションの自動追加は行いません。

## データと認証

`OrderFeedback` に依頼IDごとの本文JSONとバージョンを保存します。
依頼を完全削除するとフィードバックも削除されます。
APIとページの双方で管理者認証を行い、書き込みは既存のOriginチェックを利用します。
同時編集で古いバージョンが保存された場合は409を返し、上書きしません。
PDFは管理者がダウンロードし、既存の納品方法でクライアントに渡します。

## 本番反映

リリース前に、対象を確認したうえで既存の追加型マイグレーション手順を使います。
既存データのリセット・db push は不要です。

```sh
npm ci
npm run db:audit:check -- --deployment
npm run db:audit:apply -- --deployment
npm run build
```

追加マイグレーション：`prisma/migrations/202610270001_order_feedback/migration.sql`
`prisma generate` は既存のpostinstallで実行されます。
日本語フォントはGoogle FontsのZen Kaku Gothic Newを同梱し、SIL OFLを添付しています。
Nextのトレース設定にもフォントを含めています。

## 検証

```sh
npm run typecheck
npm test
npm run build
```

ローカルの隔離DB・テスト用認証でAPI全体を検証する場合：

```sh
node scripts/qa-environment.mjs
# 別のターミナル
node scripts/qa-feedback.mjs
```

QAスクリプトはメモリ内の検証DBであることを確認してから実行します。
検証内容：未認証・異なるOriginの拒否、不正な日付、下書き保存、未完成PDFの拒否、同時編集競合、日本語PDF、長文の改ページ。
