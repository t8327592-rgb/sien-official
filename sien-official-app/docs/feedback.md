# 録音・歌唱フィードバック

## 作成の流れ

管理画面 → 依頼管理 → 依頼詳細 →「フィードバックを作成・編集」。

1. ひとつのメモ欄へ、順不同の箇条書き・単語で気づいたことを入力。
2. 「今回が初回／前回と比較する／今回は比較しない」を選択。
3. 「AIで分類・文章案を作る」を押す。
4. 分類・仮の評価・文章案・改善方法・確認事項を読み、採用または破棄。
5. 採用すると項目別の編集欄に入るので、必要な箇所を修正。
6. 「内容を確認・修正しました」にチェックし、PDFダウンロード。

採用するまで既存の文章を置き換えません。採用時は既存の文章・評価・改善ポイントを置き換えます。
生成後も、根拠のメモとAIの確認事項を確認できます。
文章・評価・メモ・比較方法を変更すると確認チェックが外れます。
メモと確認事項は管理用に保存され、PDFには載りません。

メモにない項目は確認対象外とし、長所を創作しません。長所の欄は任意です。
曖昧な「歌唱が微妙」等は具体的な原因を創作せず確認事項に回します。
改善方法はAIの提案として確認・修正します。
初回・比較しない場合は、比較の入力欄とPDFのセクションが非表示になります。
比較する場合は、同じメールアドレスの過去の依頼から直近のフィードバック本文を参考にできます。
依頼回数だけで比較モードを自動選択しません。

## AI接続

このフィードバック機能はOpenAI Responses APIを使用し、Geminiは使用しません。
本番のサーバー環境変数 `OPENAI_API_KEY` が必要です。キーをブラウザーへ配信しません。
`OPENAI_FEEDBACK_MODEL` でモデルを指定でき、既定は `gpt-4.1-mini` です。
送信は今回のメモと、比較モード時のみ前回本文。依頼ID・名前・連絡先はメタデータに含めません。
既知のクライアント名、メール、SNS ID、電話番号、URLは既存の外部テキスト処理で置換します。
それ以外の情報をメモ内に書いた場合は送信されるため、画面にも案内を表示します。
`store: false`、JSON Schemaによる構造化出力、45秒のタイムアウト、１分６回・１日80回の共有上限を使用します。
失敗時は入力内容を維持し、明示的にエラーを表示します。他社AIへのフォールバックはありません。

## PDF・保存・認証

ホームページと同じ `public/logo.png`、白ベース・オレンジ系の差し色を使用します。
名前・楽曲名・発行日を表示し、依頼IDは表示しません。文章量に応じて改ページします。
`OrderFeedback` のJSONにメモ・比較方法・確認状態も保存します。今回の追加DB移行は不要です。
従来の保存データも読めます。旧データをPDFに出す際は一度内容を確認します。
管理者認証・同一Originの書き込み検証・バージョン競合の保護を使用します。

## リリース・検証

初回のテーブル追加については既存の追加型マイグレーション手順を使用します。
この改修のみならデータのリセット・移行・環境変数の一括変更は不要です。

```sh
npm run typecheck
npm test
npm run lint
npm run build
```

隔離DBでのAPI・PDF検証：

```sh
node scripts/qa-environment.mjs
# 別ターミナル
node scripts/qa-feedback.mjs
```
